## Критические проблемы

### 🔴 1. Отсутствие кэширования токена доступа

**Проблема:** `getAccessToken()` вызывается каждый раз без кэширования, что приводит к лишним запросам к API.

**Локация:** Строки 26-41

**Риск:**

- Лишние запросы к API СБИС
- Возможное превышение rate limits
- Медленная работа при множественных вызовах

**Решение:**

```typescript
let tokenCache: { token: string; expiresAt: number } | null = null

async getAccessToken() {
  if (tokenCache && tokenCache.expiresAt > Date.now()) {
    return { accessToken: tokenCache.token, sid: '', token: '' }
  }

  const response = await axios.post(...)
  const { access_token, sid, token, expires_in } = response.data

  // Кэшируем токен с запасом 5 минут до истечения
  tokenCache = {
    token: access_token,
    expiresAt: Date.now() + (expires_in - 300) * 1000
  }

  return { accessToken: access_token, sid, token }
}
```

### 🔴 2. Отсутствие валидации конфигурации

**Проблема:** Нет проверки наличия обязательных переменных окружения при старте.

**Локация:** Строки 7-19

**Риск:** Приложение может упасть во время выполнения, если ключи не заданы.

**Решение:**

```typescript
const getConfig = () => {
  const required = ['SBIS_APP_CLIENT_ID', 'SBIS_APP_SECRET', 'SBIS_SECRET_KEY']
  const missing = required.filter(key => !process.env[key])

  if (missing.length > 0) {
    throw new Error(`Missing required SBIS config: ${missing.join(', ')}`)
  }

  return { ... }
}
```

### 🔴 3. Неэффективная обработка больших объемов данных

**Проблема:** В `saveProducts()` и `saveCategories()` товары/категории сохраняются последовательно в цикле.

**Локация:** Строки 815-998

**Риск:**

- Очень медленная синхронизация при большом количестве товаров
- Таймауты при синхронизации тысяч товаров

**Решение:** Использовать batch операции или параллельную обработку:

```typescript
async saveProducts(products: any[], categoryStrapiIdMap?: Map<number, number | string>) {
  const BATCH_SIZE = 50
  const batches = []

  for (let i = 0; i < products.length; i += BATCH_SIZE) {
    batches.push(products.slice(i, i + BATCH_SIZE))
  }

  for (const batch of batches) {
    await Promise.all(batch.map(product => this.saveSingleProduct(product, categoryStrapiIdMap)))
  }
}
```

### 🔴 4. Потенциальная утечка памяти

**Проблема:** В `getAllProductsRecursively()` создается массив `allResponses`, который никогда не используется и не очищается.

**Локация:** Строки 204-280

**Риск:** При синхронизации большого количества страниц может произойти утечка памяти.

**Решение:** Удалить неиспользуемый код или сохранять логи в файл с ротацией.

### 🔴 5. Отсутствие обработки сетевых ошибок и retry логики

**Проблема:** При сетевой ошибке синхронизация полностью прерывается.

**Локация:** Строки 345-351, 1200-1207

**Риск:** Нестабильность при нестабильном интернете.

**Решение:** Добавить retry с экспоненциальной задержкой:

```typescript
async fetchWithRetry(url: string, options: any, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await axios.get(url, options)
    } catch (error) {
      if (i === maxRetries - 1) throw error
      await new Promise(resolve => setTimeout(resolve, Math.pow(2, i) * 1000))
    }
  }
}
```

## Проблемы производительности

### 🟡 1. Избыточное логирование

**Проблема:** В `getAllProductsRecursively()` логируется каждый ответ API в полном объеме (строки 283-301).

**Влияние:** Замедление работы и рост размера логов.

**Решение:** Логировать только ошибки и итоговую статистику, детальное логирование только в debug режиме.

### 🟡 2. Неоптимальная работа с категориями

**Проблема:** В `getAllProductsRecursively()` для каждого товара выполняется поиск корневой категории через рекурсивную функцию (строки 416-439).

**Влияние:** При большом количестве товаров это может быть медленно.

**Решение:** Предварительно построить мапу корневых категорий для всех категорий.

### 🟡 3. Последовательное сохранение в БД

**Проблема:** Все операции сохранения выполняются последовательно.

**Влияние:** Медленная синхронизация.

**Решение:** Использовать batch операции или параллельную обработку с ограничением concurrency.

## Проблемы безопасности

### 🟡 1. Отсутствие валидации входных данных

**Проблема:** Нет проверки типов и значений параметров функций.

**Пример:** `syncSalesStatistics(days = 30)` - нет проверки, что days > 0 и < разумного значения.

### 🟡 2. Логирование чувствительных данных

**Проблема:** В логах могут попадать токены и ключи (хотя сейчас это не видно явно).

**Рекомендация:** Убедиться, что в логах не попадают секретные данные.

---

## Проблемы надежности

### 🟡 1. Отсутствие транзакций

**Проблема:** При ошибке в середине синхронизации часть данных может быть сохранена, часть - нет.

**Риск:** Несогласованность данных.

**Решение:** Использовать транзакции или механизм отката.

### 🟡 2. Нет механизма восстановления после сбоя

**Проблема:** При прерывании синхронизации нет возможности продолжить с места остановки.

**Решение:** Сохранять прогресс синхронизации (например, последний обработанный ID).

### 🟡 3. Жестко заданные лимиты

**Проблема:** Лимит в 100 страниц (строка 334) может быть недостаточным для больших каталогов.

**Решение:** Сделать лимит настраиваемым через env или убрать совсем, полагаясь на проверку пустого ответа.

## Проблемы кода

### 🟡 1. Избыточная вложенность условий

**Проблема:** В `getAllProductsRecursively()` очень глубокая вложенность if-else (строки 488-693).

**Влияние:** Сложность поддержки и понимания кода.

**Решение:** Вынести логику определения корневой категории в отдельную функцию.

### 🟡 2. Дублирование кода

**Проблема:** Похожая логика поиска категории повторяется несколько раз (строки 507, 544, 578, 612).

**Решение:** Вынести в отдельную функцию.

### 🟡 3. Использование `any` типов

**Проблема:** Много использований `any`, что снижает типобезопасность.

**Решение:** Создать интерфейсы для типов данных СБИС.

### 🟡 4. Неиспользуемый код

**Проблема:**

- Массив `allResponses` создается, но не используется (строка 205)
- Переменная `logFilePath` создается, но не используется (строка 202)
- Переменная `productsInPage` вычисляется, но не используется (строка 321)

**Решение:** Удалить неиспользуемый код.
